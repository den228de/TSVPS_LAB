# КРАТКОЕ ОБЪЯСНЕНИЕ ДЛЯ ЗАЩИТЫ: ПОИСК КЛИК В ГРАФЕ

## ЧТО ТАКОЕ КЛИКА?

**Клика** - это подмножество вершин графа, в котором **каждая пара вершин соединена ребром**.

### Пример:
```
Граф:
  0 --- 1
  |  X  |
  | / \ |
  2 --- 3

Клика: {0, 1, 2, 3} - все вершины соединены между собой
Не клика: {0, 1, 2} - вершины 0 и 2 не соединены
```

---

## 1. ПРЕДСТАВЛЕНИЕ ГРАФА

В моем коде граф представлен через **матрицу смежности** - это двумерный массив, где:
- `matrix[i][j] = 1` означает, что между вершинами i и j есть ребро
- `matrix[i][j] = 0` означает, что ребра нет

### Код создания графа:

```python
class Graph:
    def __init__(self, num_vertices: int, num_edges: int):
        # Создаем матрицу смежности (все нули)
        self.adjacency_matrix = [[0] * num_vertices for _ in range(num_vertices)]
        # Генерируем случайные ребра
        self._generate_random_edges(num_edges)
```

### Пример матрицы для 4 вершин:
```
    0  1  2  3
0 [ 0  1  1  1 ]  ← вершина 0 соединена с 1, 2, 3
1 [ 1  0  1  1 ]  ← вершина 1 соединена с 0, 2, 3
2 [ 1  1  0  1 ]  ← вершина 2 соединена с 0, 1, 3
3 [ 1  1  1  0 ]  ← вершина 3 соединена с 0, 1, 2

Это полный граф - все вершины соединены между собой
```

### Генерация случайных ребер:

```python
def _generate_random_edges(self, num_edges: int):
    # Создаём список всех возможных пар вершин
    all_pairs = []
    for i in range(self.num_vertices):
        for j in range(i + 1, self.num_vertices):
            all_pairs.append((i, j))  # Например: (0,1), (0,2), (1,2)...
    
    # Перемешиваем и выбираем нужное количество рёбер
    random.shuffle(all_pairs)
    for i in range(num_edges):
        u, v = all_pairs[i]
        # Устанавливаем ребро в обе стороны (граф неориентированный)
        self.adjacency_matrix[u][v] = 1
        self.adjacency_matrix[v][u] = 1
```

**Объяснение:**
1. Создаем все возможные пары вершин (например, для 4 вершин: (0,1), (0,2), (0,3), (1,2), (1,3), (2,3))
2. Перемешиваем их случайным образом
3. Берем первые `num_edges` пар и создаем между ними ребра

## 2. ПРОВЕРКА, ЯВЛЯЕТСЯ ЛИ ПОДМНОЖЕСТВО КЛИКОЙ

Чтобы проверить, является ли набор вершин кликой, нужно убедиться, что **между каждой парой вершин есть ребро**.

### Код проверки:

```python
def is_clique(adjacency_matrix: List[List[int]], vertices: List[int]) -> bool:
    n = len(vertices)
    if n <= 1:
        return True  # Одна вершина всегда клика
    
    # Проверяем все пары вершин
    for i in range(n):
        for j in range(i + 1, n):
            u = vertices[i]
            v = vertices[j]
            # Если между вершинами нет ребра - это НЕ клика
            if adjacency_matrix[u][v] == 0:
                return False
    
    return True  # Все пары соединены - это клика!
```

### Пример работы:

```
Проверяем вершины [0, 1, 2]

Шаг 1: i=0, j=1 → проверяем вершины 0 и 1
       adjacency_matrix[0][1] = 1 ✓ (есть ребро)

Шаг 2: i=0, j=2 → проверяем вершины 0 и 2
       adjacency_matrix[0][2] = 1 ✓ (есть ребро)

Шаг 3: i=1, j=2 → проверяем вершины 1 и 2
       adjacency_matrix[1][2] = 0 ✗ (НЕТ ребра!)
       
Результат: НЕ клика (вершины 1 и 2 не соединены)
```

## 3. ПОИСК КЛИКИ БОЛЬШЕ B

Задача: найти клику размером **больше** заданного числа B.

### Алгоритм:

1. Перебираем размеры клики от B+1 до количества вершин
2. Для каждого размера генерируем **все возможные комбинации** вершин
3. Проверяем каждую комбинацию - является ли она кликой
4. Возвращаем **первую найденную** клику

### Код:

```python
def find_clique_greater_than_b(adjacency_matrix: List[List[int]], b: int) -> List[int]:
    num_vertices = len(adjacency_matrix)
    
    # Перебираем размеры клики от B+1 до количества вершин
    for k in range(b + 1, num_vertices + 1):
        # Генерируем все комбинации из k вершин
        # combinations(range(5), 3) → (0,1,2), (0,1,3), (0,1,4), (0,2,3)...
        for combo in combinations(range(num_vertices), k):
            combo_list = list(combo)
            # Проверяем, является ли комбинация кликой
            if is_clique(adjacency_matrix, combo_list):
                return combo_list  # Нашли! Возвращаем
    
    return []  # Не нашли клику больше B
```

### Пример работы:

```
Граф с 5 вершинами, B = 2 (ищем клику размером >= 3)

k=3: Проверяем все комбинации из 3 вершин
     (0,1,2) → проверяем → НЕ клика
     (0,1,3) → проверяем → НЕ клика
     (0,2,3) → проверяем → КЛИКА! ✓
     Возвращаем [0, 2, 3]
```

### Что такое combinations?

`combinations(range(5), 3)` генерирует все способы выбрать 3 элемента из 5:
```
(0, 1, 2)
(0, 1, 3)
(0, 1, 4)
(0, 2, 3)
(0, 2, 4)
(0, 3, 4)
(1, 2, 3)
(1, 2, 4)
(1, 3, 4)
(2, 3, 4)
```

## 4. ПОИСК МАКСИМАЛЬНОЙ КЛИКИ

Задача: найти клику **максимального размера** в графе.

### Алгоритм (обратный перебор):

1. Начинаем с **максимального** возможного размера (количество вершин)
2. Уменьшаем размер, пока не найдем клику
3. Первая найденная клика и будет максимальной

**Почему с конца?** Потому что мы ищем **максимальную** клику. Если начнем с большого размера, то первая найденная клика гарантированно будет максимальной.

### Код:

```python
def find_max_clique(adjacency_matrix: List[List[int]], callback=None) -> List[int]:
    num_vertices = len(adjacency_matrix)
    max_clique = []
    
    # Перебираем размеры от максимального к минимальному
    for k in range(num_vertices, 0, -1):  # n, n-1, n-2, ..., 1
        combo_count = 0
        
        # Генерируем все комбинации из k вершин
        for combo in combinations(range(num_vertices), k):
            combo_count += 1
            combo_list = list(combo)
            
            # Формируем строку для вывода
            combo_str = "{" + ", ".join(map(str, combo_list)) + "}"
            output = f"{combo_str}, №{combo_count}"
            
            # Проверяем, является ли комбинация кликой
            if is_clique(adjacency_matrix, combo_list):
                output += "     - клика"
                if len(combo_list) > len(max_clique):
                    max_clique = combo_list
                    output += " - максимальная клика"
                    if callback:
                        callback(output + "\n")
                    # Нашли максимальную клику, выходим!
                    return max_clique
            
            if callback:
                callback(output + "\n")
    
    return max_clique
```

### Пример работы:

```
Граф с 5 вершинами

k=5: Проверяем комбинацию (0,1,2,3,4)
     → НЕ клика (не все соединены)

k=4: Проверяем все комбинации из 4 вершин
     (0,1,2,3) → НЕ клика
     (0,1,2,4) → НЕ клика
     (0,1,3,4) → НЕ клика
     (0,2,3,4) → НЕ клика
     (1,2,3,4) → НЕ клика

k=3: Проверяем все комбинации из 3 вершин
     (0,1,2) → НЕ клика
     (0,1,3) → КЛИКА! ✓
     
Результат: Максимальная клика = [0, 1, 3], размер = 3
```

### Вывод процесса:

Функция `callback` используется для вывода процесса поиска в реальном времени:
```python
if callback:
    callback(f"\nn={num_vertices}, k={k}, все комбинации №{num_vertices - k + 1}:\n")
```

Это позволяет видеть, какие комбинации проверяются и какие из них являются кликами.

## 5. ВИЗУАЛИЗАЦИЯ ГРАФА

Граф рисуется в ASCII формате, где:
- `o` - обычная вершина
- `*` - вершина из клики больше B
- `#` - вершина из максимальной клики
- `-` - ребро между вершинами

### Код расположения вершин по кругу:

```python
def generate_ascii_graph(adjacency_matrix, clique_b, max_clique, width=90, height=60):
    import math
    
    num_vertices = len(adjacency_matrix)
    center_x = width // 2
    center_y = height // 2
    radius = min(center_x, center_y) * 0.8
    
    # Вычисляем позиции вершин по кругу
    positions = []
    for i in range(num_vertices):
        angle = 2.0 * math.pi * i / num_vertices  # Угол для каждой вершины
        x = int(center_x + radius * math.cos(angle))
        y = int(center_y + radius * math.sin(angle))
        positions.append((x, y))
```

**Объяснение:**
1. Вершины располагаются **по кругу** для лучшей визуализации
2. Угол для каждой вершины: `360° / количество_вершин`
3. Координаты вычисляются через `cos` и `sin`

### Рисование ребер (алгоритм Брезенхема):

```python
# Рисуем рёбра (линии между вершинами)
for i in range(num_vertices):
    for j in range(i + 1, num_vertices):
        if adjacency_matrix[i][j] == 1:  # Если есть ребро
            x1, y1 = positions[i]
            x2, y2 = positions[j]
            
            # Алгоритм Брезенхема для рисования линии
            dx = abs(x2 - x1)
            dy = abs(y2 - y1)
            sx = 1 if x1 < x2 else -1
            sy = 1 if y1 < y2 else -1
            err = dx - dy
            
            x, y = x1, y1
            while True:
                if 0 <= x < width and 0 <= y < height:
                    screen[y][x] = '-'  # Рисуем символ линии
                
                if x == x2 and y == y2:
                    break
                
                # Вычисляем следующую точку
                e2 = 2 * err
                if e2 > -dy:
                    err -= dy
                    x += sx
                if e2 < dx:
                    err += dx
                    y += sy
```

**Алгоритм Брезенхема** - это классический алгоритм для рисования линий на растровом экране. Он определяет, какие пиксели нужно закрасить, чтобы получить прямую линию между двумя точками.

### Рисование вершин:

```python
# Рисуем вершины (поверх рёбер)
```

## ИТОГО ДЛЯ ЗАЩИТЫ:

### 1. Представление графа
- Матрица смежности: `matrix[i][j] = 1` если есть ребро
- Генерация случайных ребер: перемешиваем все пары и выбираем нужное количество

### 2. Проверка клики
- Перебираем все пары вершин в подмножестве
- Если хотя бы одна пара не соединена → НЕ клика

### 3. Поиск клики больше B
- Перебираем размеры от B+1 до n
- Генерируем все комбинации вершин
- Возвращаем первую найденную клику

### 4. Поиск максимальной клики
- **Обратный перебор**: начинаем с максимального размера
- Первая найденная клика = максимальная
- Оптимизация: не нужно проверять меньшие размеры

### 5. Визуализация
- Вершины по кругу (через `cos` и `sin`)
- Ребра рисуются алгоритмом Брезенхема
- Разные символы для разных типов вершин

---

## СЛОЖНОСТЬ АЛГОРИТМОВ

**Проверка клики**: O(k²), где k - размер подмножества

**Поиск клики больше B**: O(C(n,k) × k²), где C(n,k) - биномиальный коэффициент

**Поиск максимальной клики**: O(2^n × n²) в худшем случае (экспоненциальная сложность)

**Почему так медленно?** Задача поиска максимальной клики - это **NP-полная задача**, для которой не существует быстрого (полиномиального) алгоритма.
