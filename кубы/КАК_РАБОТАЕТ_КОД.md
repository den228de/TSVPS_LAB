# КАК РАБОТАЕТ МОЯ ПРОГРАММА hypercube_network.py

## ОБЩАЯ СТРУКТУРА ПРОГРАММЫ

Моя программа состоит из **двух основных классов**:

1. **`SingleHypercube`** - представляет один гиперкуб
2. **`MultiCubeNetwork`** - представляет сеть из нескольких гиперкубов, соединенных в кольцо

---

## ПОШАГОВОЕ ОБЪЯСНЕНИЕ РАБОТЫ ПРОГРАММЫ

### ШАГ 1: Создание одного гиперкуба (класс `SingleHypercube`)

**Что происходит при создании гиперкуба:**

```python
cube = SingleHypercube(dimension=3)
```

1. **Инициализация (метод `__init__`):**
   - Сохраняю размерность куба: `self.dimension = 3`
   - Вычисляю количество процессоров: `self.total_processors = 2^3 = 8`
   - Создаю пустую матрицу смежности 8×8 (все нули)
   - Вызываю метод `_build_hypercube()` для построения связей

2. **Построение гиперкуба (метод `_build_hypercube`):**
   - Для каждого процессора `i` от 0 до 7:
     - Для каждого бита `j` от 0 до 2 (размерность):
       - Инвертирую j-й бит числа i: `neighbor = i ^ (1 << j)`
       - Устанавливаю связь в матрице: `adjacency_matrix[i][neighbor] = 1`
   
   **Пример:** процессор 5 (бинарно: `101`)
   - Бит 0: `5 ^ 1 = 4` → связь 5-4
   - Бит 1: `5 ^ 2 = 7` → связь 5-7
   - Бит 2: `5 ^ 4 = 1` → связь 5-1

3. **Дополнительные методы:**
   - `get_binary_representation(processor_id)` - преобразует ID в двоичную строку
   - `get_neighbors(processor_id)` - возвращает список соседей процессора

### ШАГ 2: Создание сети из нескольких кубов (класс `MultiCubeNetwork`)

**Что происходит при создании сети:**

```python
network = MultiCubeNetwork(num_cubes=2, dimension_per_cube=3)
```

1. **Инициализация (метод `__init__`):**
   - Сохраняю параметры:
     - `self.num_cubes = 2` (количество кубов)
     - `self.dimension_per_cube = 3` (размерность каждого)
     - `self.processors_per_cube = 2^3 = 8` (процессоров в кубе)
     - `self.total_processors = 2 × 8 = 16` (всего процессоров)
   
   - Создаю 2 отдельных гиперкуба:
     ```python
     self.cubes = [SingleHypercube(3), SingleHypercube(3)]
     ```
   
   - Создаю объединенную матрицу смежности 16×16
   - Вызываю `_build_combined_topology()` для соединения кубов

2. **Построение объединенной топологии (метод `_build_combined_topology`):**
   
   **Часть 1: Копирование внутренних связей каждого куба**
   - Для каждого куба (0 и 1):
     - Для каждой пары процессоров внутри куба:
       - Если они соединены в локальной матрице:
         - Преобразую локальные ID в глобальные через `_encode_address()`
         - Копирую связь в объединенную матрицу
   
   **Часть 2: Соединение кубов в кольцо**
   - Для каждого куба:
     - Определяю следующий куб: `next_cube = (cube_id + 1) % num_cubes`
     - Для каждого процессора i в текущем кубе:
       - Соединяю процессор i текущего куба с процессором i следующего куба
   
   **Пример:** Куб 0 → Куб 1 → Куб 0 (кольцо)
   - Процессор 0 куба 0 (глобально 0) ↔ Процессор 0 куба 1 (глобально 8)
   - Процессор 1 куба 0 (глобально 1) ↔ Процессор 1 куба 1 (глобально 9)
   - И так далее...

3. **Глобальная адресация:**
   
   **Кодирование (метод `_encode_address`):**
   ```python
   global_id = cube_id * processors_per_cube + processor_id_within_cube
   ```
   - Куб 0, процессор 5: `0 × 8 + 5 = 5`
   - Куб 1, процессор 3: `1 × 8 + 3 = 11`
   
   **Декодирование (метод `_decode_address`):**
   ```python
   processor_id_within_cube = global_id % processors_per_cube
   cube_id = global_id // processors_per_cube
   ```
   - Глобальный ID 11: `11 % 8 = 3` (процессор), `11 // 8 = 1` (куб)

### ШАГ 3: Поиск кратчайшего пути (метод `find_shortest_path`)

**Что происходит при поиске пути:**

```python
path = network.find_shortest_path(source=1, destination=11)
```

1. **Проверка тривиального случая:**
   - Если `source == destination`, возвращаю `[source]`

2. **Инициализация BFS:**
   - Создаю очередь: `queue = [1]`
   - Создаю словарь родителей: `parent = {1: None}`
   - Создаю множество посещенных: `visited = {1}`

3. **Основной цикл BFS:**
   ```
   Пока очередь не пуста:
     1. Извлекаю текущий процессор из очереди
     2. Если это конечный процессор → выхожу из цикла
     3. Для каждого соседа текущего процессора:
        - Если сосед не посещен:
          - Добавляю в visited
          - Запоминаю родителя: parent[сосед] = текущий
          - Добавляю соседа в очередь
   ```

4. **Восстановление пути:**
   ```python
   path = []
   current = destination  # Начинаю с конца
   while current is not None:
       path.append(current)
       current = parent[current]  # Иду к родителю
   path.reverse()  # Переворачиваю путь
   ```
   
   **Пример:** путь от 1 до 11
   - Родители: `{1: None, 0: 1, 3: 1, 5: 1, 9: 1, 11: 9}`
   - Восстановление: `11 ← 9 ← 1`
   - Путь: `[1, 9, 11]`

## КРАТКОЕ РЕЗЮМЕ ДЛЯ ЗАЩИТЫ

**Когда преподаватель спросит "Как работает твоя программа?", говорю:**

> "Моя программа работает в три этапа:
> 
> **Первый этап** - создание одного гиперкуба. Я создаю класс `SingleHypercube`, который принимает размерность N. В конструкторе я вычисляю количество процессоров как 2 в степени N, создаю матрицу смежности и вызываю метод `_build_hypercube()`. Этот метод проходит по всем процессорам и для каждого процессора инвертирует каждый бит его двоичного представления с помощью операции XOR, чтобы найти всех N соседей. Связи записываются в матрицу смежности.
> 
> **Второй этап** - объединение нескольких кубов в сеть. Класс `MultiCubeNetwork` создает несколько объектов `SingleHypercube` и объединяет их в кольцевую топологию. Сначала я копирую все внутренние связи каждого куба в общую матрицу смежности, используя глобальную адресацию. Затем соединяю соответствующие процессоры соседних кубов - процессор i в кубе K соединяется с процессором i в кубе K+1. Последний куб соединяется с первым, образуя кольцо.
> 
> **Третий этап** - поиск кратчайшего пути. Я использую алгоритм BFS (поиск в ширину). Начинаю с исходного процессора, добавляю его в очередь и помечаю как посещенный. Затем в цикле извлекаю процессор из очереди, проверяю всех его соседей по матрице смежности, и если сосед не был посещен, добавляю его в очередь и запоминаю родителя. Когда нахожу конечный процессор, восстанавливаю путь, идя от конца к началу по цепочке родителей, и переворачиваю результат."

## КЛЮЧЕВЫЕ МОМЕНТЫ ДЛЯ ЗАПОМИНАНИЯ

✅ **XOR операция** - `i ^ (1 << j)` инвертирует j-й бит числа i  
✅ **Матрица смежности** - двумерный массив, где 1 означает наличие связи  
✅ **Глобальная адресация** - `cube_id × processors_per_cube + local_id`  
✅ **Кольцевая топология** - последний куб соединяется с первым через `% num_cubes`  
✅ **BFS** - обход по уровням гарантирует кратчайший путь  
✅ **Восстановление пути** - идем от конца к началу по родителям и переворачиваем
