# РУКОВОДСТВО ДЛЯ ЗАЩИТЫ ПРОЕКТА: СИМУЛЯЦИЯ СЕТИ ГИПЕРКУБОВ

## 1. ОПИСАНИЕ ЗАДАЧИ И ЦЕЛЕЙ ПРОГРАММЫ

### Цель проекта
Разработка программного обеспечения для симуляции топологии сети гиперкубов и поиска кратчайших путей между процессорами в такой сети.

### Основные задачи
1. **Моделирование гиперкуба** - создание структуры данных для представления гиперкуба произвольной размерности
2. **Объединение гиперкубов** - соединение нескольких гиперкубов в кольцевую топологию
3. **Поиск кратчайших путей** - реализация алгоритма BFS для нахождения оптимального маршрута между процессорами
4. **Визуализация** - графическое представление топологии сети и найденных путей

### Практическое применение
- Моделирование параллельных вычислительных систем
- Анализ топологий многопроцессорных систем
- Оптимизация маршрутизации в распределенных системах
- Исследование свойств гиперкубических топологий

## 2. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ

### 2.1 Что такое гиперкуб?

**Гиперкуб размерности n** (обозначается Q_n) - это граф, который содержит:
- **Вершины**: 2^n процессоров
- **Ребра**: каждый процессор соединен ровно с n соседями

**Ключевое свойство**: два процессора соединены ребром тогда и только тогда, когда их бинарные представления отличаются ровно в одном бите.

#### Примеры:

**Q_1 (одномерный гиперкуб - отрезок)**
```
0 ─── 1
```
- 2 вершины: 0 (бинарно: 0), 1 (бинарно: 1)
- Отличаются в 1 бите

**Q_2 (двумерный гиперкуб - квадрат)**
```
00 ─── 01
 |      |
 |      |
10 ─── 11
```
- 4 вершины: 00, 01, 10, 11
- Каждая вершина имеет 2 соседа

**Q_3 (трехмерный гиперкуб - куб)**
```
    100 ─── 101
    /|      /|
  /  |    /  |
000 ─── 001  |
 |  110 ─|─ 111
 |  /    | /
 |/      |/
010 ─── 011
```
- 8 вершин: 000, 001, 010, 011, 100, 101, 110, 111
- Каждая вершина имеет 3 соседа

### 2.2 Свойства гиперкуба

1. **Регулярность**: все вершины имеют одинаковую степень (n соседей)
2. **Симметричность**: граф выглядит одинаково из любой вершины
3. **Малый диаметр**: максимальное расстояние между любыми двумя вершинами = n
4. **Высокая связность**: устойчивость к отказам узлов
5. **Рекурсивная структура**: Q_n можно построить из двух Q_(n-1)

### 3.2 Модуль hypercube_network.py

#### Класс `SingleHypercube`

**Назначение**: представление одного гиперкуба

**Основные атрибуты**:
- `dimension` - размерность гиперкуба (n)
- `total_processors` - количество процессоров (2^n)
- `adjacency_matrix` - матрица смежности (связи между процессорами)

**Ключевые методы**:

1. **`__init__(dimension)`** - конструктор
   - Инициализирует размерность
   - Вычисляет количество процессоров
   - Создает матрицу смежности
   - Вызывает построение гиперкуба

2. **`_build_hypercube()`** - построение матрицы смежности
   ```python
   for i in range(total_processors):
       for j in range(dimension):
           neighbor = i ^ (1 << j)  # XOR для инвертирования j-го бита
           adjacency_matrix[i][neighbor] = 1
   ```
   
   **Объяснение алгоритма**:
   - Для каждого процессора i
   - Перебираем все биты (от 0 до dimension-1)
   - Инвертируем j-й бит с помощью XOR
   - Получаем ID соседа
   - Устанавливаем связь в матрице смежности

   **Пример**: процессор 5 (бинарно: 101) в Q_3
   - Инвертируем бит 0: 101 ^ 001 = 100 (процессор 4)
   - Инвертируем бит 1: 101 ^ 010 = 111 (процессор 7)
   - Инвертируем бит 2: 101 ^ 100 = 001 (процессор 1)
   - Соседи: 4, 7, 1

3. **`get_binary_representation(processor_id)`** - получение бинарного представления
   - Преобразует ID процессора в двоичную строку
   - Дополняет нулями до нужной длины

4. **`get_neighbors(processor_id)`** - получение списка соседей
   - Просматривает строку матрицы смежности
   - Возвращает ID всех соседних процессоров

#### Класс `MultiCubeNetwork`

**Назначение**: сеть из нескольких гиперкубов, соединенных в кольцо

**Основные атрибуты**:
- `num_cubes` - количество кубов в сети
- `dimension_per_cube` - размерность каждого куба
- `processors_per_cube` - процессоров в одном кубе
- `total_processors` - общее количество процессоров
- `cubes` - список объектов SingleHypercube
- `combined_adjacency_matrix` - объединенная матрица смежности

**Ключевые методы**:

1. **`_build_combined_topology()`** - построение объединенной топологии
   
   **Шаг 1**: Копирование связей внутри каждого куба
   ```python
   for cube_id in range(num_cubes):
       # Для каждой пары процессоров в кубе
       # Если они соединены внутри куба
       # Добавляем связь в объединенную матрицу
   ```
   
   **Шаг 2**: Соединение кубов в кольцо
   ```python
   for cube_id in range(num_cubes):
       next_cube_id = (cube_id + 1) % num_cubes
       # Соединяем процессор i в текущем кубе
       # с процессором i в следующем кубе
   ```
   
   **Топология кольца**: куб 0 → куб 1 → куб 2 → ... → куб (n-1) → куб 0

2. **`_encode_address(cube_id, processor_id_within_cube)`** - кодирование адреса
   ```python
   global_id = cube_id * processors_per_cube + processor_id_within_cube
   ```
   
   **Пример**: 2 куба размерности 3 (по 8 процессоров)
   - Куб 0, процессор 5: global_id = 0 * 8 + 5 = 5
   - Куб 1, процессор 3: global_id = 1 * 8 + 3 = 11

3. **`_decode_address(global_id)`** - декодирование адреса
   ```python
   processor_id_within_cube = global_id % processors_per_cube
   cube_id = global_id // processors_per_cube
   ```

4. **`find_shortest_path(source, destination)`** - поиск кратчайшего пути (BFS)

## 4. АЛГОРИТМ BFS (ПОИСК В ШИРИНУ)

### 4.1 Описание алгоритма

**BFS (Breadth-First Search)** - алгоритм обхода графа, который исследует вершины по уровням:
1. Сначала посещаем начальную вершину
2. Затем всех её соседей (уровень 1)
3. Затем соседей соседей (уровень 2)
4. И так далее...

### 4.2 Почему BFS находит кратчайший путь?

В **невзвешенном графе** (все ребра имеют одинаковый вес = 1):
- BFS гарантированно находит путь с минимальным количеством ребер
- Первый найденный путь = кратчайший путь

### 4.3 Реализация в программе

```python
def find_shortest_path(source, destination):
    # 1. Инициализация
    queue = deque([source])        # Очередь для BFS
    parent = {source: None}        # Для восстановления пути
    visited = {source}             # Посещенные вершины
    
    # 2. Основной цикл BFS
    while queue:
        current = queue.popleft()  # Берем вершину из очереди
        
        if current == destination:  # Нашли цель
            break
        
        # 3. Обрабатываем всех соседей
        for neighbor in range(total_processors):
            if adjacency_matrix[current][neighbor] and neighbor not in visited:
                visited.add(neighbor)
                parent[neighbor] = current
                queue.append(neighbor)
    
    # 4. Восстановление пути
    path = []
    current = destination
    while current is not None:
        path.append(current)
        current = parent[current]
    path.reverse()
    
    return path
```

### 4.4 Пример работы BFS

**Задача**: найти путь от процессора 0 до процессора 7 в Q_3

```
Шаг 0: queue = [0], visited = {0}
Шаг 1: Обрабатываем 0, добавляем соседей 1, 2, 4
       queue = [1, 2, 4], visited = {0, 1, 2, 4}
Шаг 2: Обрабатываем 1, добавляем соседей 3, 5
       queue = [2, 4, 3, 5], visited = {0, 1, 2, 3, 4, 5}
Шаг 3: Обрабатываем 2, добавляем соседа 6
       queue = [4, 3, 5, 6], visited = {0, 1, 2, 3, 4, 5, 6}
Шаг 4: Обрабатываем 4, нет новых соседей
Шаг 5: Обрабатываем 3, добавляем соседа 7
       queue = [5, 6, 7], visited = {0, 1, 2, 3, 4, 5, 6, 7}
Шаг 6: Обрабатываем 5, нашли 7 - СТОП!

Восстановление пути:
7 ← 3 ← 1 ← 0
Путь: 0 → 1 → 3 → 7 (длина 3)
```

### 4.5 Сложность алгоритма

- **Временная сложность**: O(V + E), где V - вершины, E - ребра
  - Для гиперкуба Q_n: O(2^n * n)
- **Пространственная сложность**: O(V) для хранения очереди и visited

## 7. ВОЗМОЖНЫЕ ВОПРОСЫ И ОТВЕТЫ ДЛЯ ЗАЩИТЫ

### Вопрос 1: Почему используется операция XOR для построения гиперкуба?

**Ответ**: 
XOR (исключающее ИЛИ) инвертирует конкретный бит, не затрагивая остальные. Операция `i ^ (1 << j)` инвертирует j-й бит числа i, что дает ID соседа, отличающегося ровно в одном бите. Это соответствует определению гиперкуба.

### Вопрос 2: Почему BFS гарантирует нахождение кратчайшего пути?

**Ответ**:
BFS исследует граф по уровням. Все вершины на расстоянии k от начальной вершины будут посещены раньше, чем вершины на расстоянии k+1. Поэтому первый найденный путь до целевой вершины будет иметь минимальную длину.

### Вопрос 3: Какова максимальная длина кратчайшего пути в гиперкубе Q_n?

**Ответ**:
Максимальная длина = n (размерность куба). Это происходит, когда два процессора отличаются во всех битах (например, 000...0 и 111...1). Каждый шаг пути изменяет один бит, поэтому нужно n шагов.

### Вопрос 4: Зачем нужна кольцевая топология при объединении кубов?

**Ответ**:
Кольцевая топология обеспечивает:
1. Регулярность - каждый куб соединен с двумя соседями
2. Отказоустойчивость - есть два пути между любыми кубами
3. Простоту реализации - легко масштабировать
4. Симметричность - нет выделенных узлов

### Вопрос 5: Какие преимущества у гиперкубической топологии?

**Ответ**:
1. **Малый диаметр** - O(log N) для N процессоров
2. **Высокая связность** - много альтернативных путей
3. **Масштабируемость** - легко добавлять процессоры (удваивая их число)
4. **Симметричность** - все узлы равноправны
5. **Эффективная маршрутизация** - простые алгоритмы поиска пути

### Вопрос 6: Как работает кодирование глобального адреса?

**Ответ**:
Глобальный ID = cube_id * processors_per_cube + processor_id_within_cube

Это линейное отображение двумерного адреса (куб, процессор) в одномерный глобальный ID. Декодирование выполняется через деление с остатком.

### Вопрос 7: Можно ли использовать другие алгоритмы поиска пути?

**Ответ**:
Да, можно использовать:
- **DFS** (поиск в глубину) - но не гарантирует кратчайший путь
- **Dijkstra** - для взвешенных графов (избыточен для невзвешенных)
- **A*** - с эвристикой (расстояние Хэмминга между бинарными представлениями)
- **Bidirectional BFS** - BFS с двух концов (быстрее для больших графов)

Для невзвешенного графа BFS - оптимальный выбор по простоте и эффективности.

### Вопрос 8: Какова сложность хранения матрицы смежности?

**Ответ**:
Для гиперкуба Q_n с 2^n вершинами матрица смежности требует O((2^n)^2) = O(4^n) памяти. Это экспоненциальный рост. Для больших n эффективнее использовать список смежности, который требует O(n * 2^n) памяти (каждая из 2^n вершин имеет n соседей).

### Вопрос 9: Как визуализация помогает понять топологию?

**Ответ**:
Визуализация позволяет:
1. Увидеть структуру связей между процессорами
2. Различить разные кубы по цвету
3. Проследить найденный путь
4. Понять, как кубы соединены в кольцо
5. Оценить симметричность и регулярность топологии

### Вопрос 10: Какие ограничения у текущей реализации?

**Ответ**:
1. **Размерность ограничена 10** - из-за экспоненциального роста памяти
2. **Матрица смежности** - неэффективна для больших графов
3. **Только кольцевая топология** - можно реализовать другие (решетка, тор)
4. **Невзвешенный граф** - все ребра имеют вес 1
