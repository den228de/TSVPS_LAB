# КРАТКОЕ ОБЪЯСНЕНИЕ ДЛЯ ЗАЩИТЫ: ГИПЕРКУБЫ

## ЧТО ТАКОЕ ГИПЕРКУБ?

**Гиперкуб размерности n (Q_n)** - это граф с 2^n вершинами (процессорами), где два процессора соединены ребром тогда и только тогда, когда их **бинарные представления отличаются ровно в одном бите**.

### Примеры:

**Q_1 (отрезок):**
```
0 ─── 1
```

**Q_2 (квадрат):**
```
00 ─── 01
 |      |
10 ─── 11
```

**Q_3 (куб):**
```
    100 ─── 101
    /|      /|
  /  |    /  |
000 ─── 001  |
 |  110 ─|─ 111
 |  /    | /
 |/      |/
010 ─── 011
```

---

## 1. ПОСТРОЕНИЕ ГИПЕРКУБА

### Алгоритм построения матрицы смежности:

Для каждого процессора `i` находим его соседей, **инвертируя каждый бит** его бинарного представления.

### Код:

```python
for i in range(total_processors):
    for j in range(dimension):
        neighbor = i ^ (1 << j)  # XOR для инвертирования j-го бита
        adjacency_matrix[i][neighbor] = 1
```

### Как это работает:

**Операция XOR (^)** инвертирует конкретный бит:
- `1 << j` создает число с единицей в j-й позиции (например: `1 << 2 = 100`)
- `i ^ (1 << j)` инвертирует j-й бит числа i

**Пример:** процессор 5 (бинарно: `101`) в Q_3
- Инвертируем бит 0: `101 ^ 001 = 100` → сосед 4
- Инвертируем бит 1: `101 ^ 010 = 111` → сосед 7
- Инвертируем бит 2: `101 ^ 100 = 001` → сосед 1
- **Соседи процессора 5: [4, 7, 1]**

## 2. ОБЪЕДИНЕНИЕ КУБОВ В КОЛЬЦО

Когда у нас несколько гиперкубов, мы соединяем их в **кольцевую топологию**:

```
Куб 0 → Куб 1 → Куб 2 → ... → Куб (n-1) → Куб 0
```

### Алгоритм соединения:

```python
for cube_id in range(num_cubes):
    next_cube_id = (cube_id + 1) % num_cubes
    # Соединяем процессор i в текущем кубе
    # с процессором i в следующем кубе
```

### Глобальная адресация:

**Кодирование:**
```python
global_id = cube_id * processors_per_cube + processor_id_within_cube
```

**Пример:** 2 куба размерности 3 (по 8 процессоров)
- Куб 0, процессор 5: `global_id = 0 * 8 + 5 = 5`
- Куб 1, процессор 3: `global_id = 1 * 8 + 3 = 11`

**Декодирование:**
```python
processor_id_within_cube = global_id % processors_per_cube
cube_id = global_id // processors_per_cube
```

## 3. ПОИСК КРАТЧАЙШЕГО ПУТИ (BFS)

**BFS (Breadth-First Search)** - алгоритм обхода графа, который исследует вершины **по уровням**.

### Почему BFS находит кратчайший путь?

В **невзвешенном графе** (все ребра имеют вес = 1):
- BFS гарантированно находит путь с **минимальным количеством ребер**
- **Первый найденный путь = кратчайший путь**

### Алгоритм:

```python
def find_shortest_path(source, destination):
    # 1. Инициализация
    queue = [source]              # Очередь для BFS
    parent = {source: None}       # Для восстановления пути
    visited = {source}            # Посещенные вершины
    
    # 2. Основной цикл BFS
    while queue:
        current = queue.pop(0)    # Берем вершину из очереди
        
        if current == destination:  # Нашли цель!
            break
        
        # 3. Обрабатываем всех соседей
        for neighbor in get_neighbors(current):
            if neighbor not in visited:
                visited.add(neighbor)
                parent[neighbor] = current
                queue.append(neighbor)
    
    # 4. Восстановление пути
    path = []
    current = destination
    while current is not None:
        path.append(current)
        current = parent[current]
    path.reverse()
    
    return path
```

### Пример работы:

**Задача:** найти путь от процессора 0 до процессора 7 в Q_3

```
Шаг 1: Начинаем с 0, добавляем соседей: 1, 2, 4
Шаг 2: Обрабатываем 1, добавляем соседей: 3, 5
Шаг 3: Обрабатываем 2, добавляем соседа: 6
Шаг 4: Обрабатываем 4, нет новых соседей
Шаг 5: Обрабатываем 3, добавляем соседа: 7 ✓ НАШЛИ!

Восстановление пути:
7 ← 3 ← 1 ← 0

Путь: 0 → 1 → 3 → 7 (длина 3)
```

### Сложность алгоритма:

- **Временная сложность:** O(V + E), где V - вершины, E - ребра
  - Для гиперкуба Q_n: O(2^n × n)
- **Пространственная сложность:** O(V)

## 4. СКОЛЬКО СОСЕДЕЙ У ВЕРШИНЫ В ГИПЕРКУБЕ Q_N?

**Ответ: У каждой вершины в гиперкубе размерности N ровно N соседей.**

### Почему именно N соседей?

Каждая вершина представлена **N-битным двоичным числом**. Сосед получается **инвертированием одного бита**. Поскольку у нас N битов, мы можем инвертировать каждый из них, получая ровно **N различных соседей**.

### Примеры по размерностям:

**Q_1 (одномерный гиперкуб):**
- **Размерность:** 1 → **Соседей:** 1
```
Вершина 0 (бинарно: 0) → сосед: 1
Вершина 1 (бинарно: 1) → сосед: 0
```

**Q_2 (двумерный гиперкуб - квадрат):**
- **Размерность:** 2 → **Соседей:** 2
```
Вершина 00 → соседи: 01, 10 (инвертируем бит 0 или бит 1)
Вершина 01 → соседи: 00, 11
Вершина 10 → соседи: 00, 11
Вершина 11 → соседи: 01, 10
```

**Q_3 (трехмерный гиперкуб - куб):**
- **Размерность:** 3 → **Соседей:** 3

Пример: вершина 5 (бинарно: `101`)
- Инвертируем бит 0: `101 ^ 001 = 100` → сосед **4**
- Инвертируем бит 1: `101 ^ 010 = 111` → сосед **7**
- Инвертируем бит 2: `101 ^ 100 = 001` → сосед **1**
- **Итого: 3 соседа [4, 7, 1]**

**Q_4 (четырехмерный гиперкуб):**
- **Размерность:** 4 → **Соседей:** 4

Пример: вершина 5 (бинарно: `0101`)
- Инвертируем бит 0: `0101 ^ 0001 = 0100` → сосед **4**
- Инвертируем бит 1: `0101 ^ 0010 = 0111` → сосед **7**
- Инвертируем бит 2: `0101 ^ 0100 = 0001` → сосед **1**
- Инвертируем бит 3: `0101 ^ 1000 = 1101` → сосед **13**
- **Итого: 4 соседа [4, 7, 1, 13]**

### Общая таблица:

| Размерность (N) | Всего вершин | Соседей у каждой | Всего ребер |
|-----------------|--------------|------------------|-------------|
| 1 | 2 | **1** | 1 |
| 2 | 4 | **2** | 4 |
| 3 | 8 | **3** | 12 |
| 4 | 16 | **4** | 32 |
| 5 | 32 | **5** | 80 |
| N | 2^N | **N** | N × 2^(N-1) |

### Как это работает в коде:

```python
# Для каждой вершины i находим N соседей
for i in range(total_processors):  # Перебираем все вершины
    for j in range(dimension):      # Перебираем все N битов
        neighbor = i ^ (1 << j)     # Инвертируем j-й бит
        adjacency_matrix[i][neighbor] = 1
```

**Объяснение:**
- Внешний цикл `for i` проходит по всем вершинам
- Внутренний цикл `for j in range(dimension)` проходит ровно **N раз** (от 0 до N-1)
- На каждой итерации мы инвертируем один бит → получаем одного соседа
- **Итого: N соседей для каждой вершины**

### Важное свойство:

Гиперкуб - это **регулярный граф**, где **все вершины имеют одинаковую степень = N**. Это очень важно для параллельных вычислительных систем, так как обеспечивает симметричность и равномерную нагрузку на все процессоры.

---

## 5. СВОЙСТВА ГИПЕРКУБА

1. **Регулярность:** все вершины имеют одинаковую степень (n соседей)
2. **Симметричность:** граф выглядит одинаково из любой вершины
3. **Малый диаметр:** максимальное расстояние между любыми двумя вершинами = n
4. **Высокая связность:** устойчивость к отказам узлов
5. **Рекурсивная структура:** Q_n можно построить из двух Q_(n-1)

## ИТОГО ДЛЯ ЗАЩИТЫ:

### Построение гиперкуба:
- Используем операцию XOR для инвертирования битов
- Для каждого процессора инвертируем каждый бит → получаем соседей
- Сложность: O(n × 2^n)

### Объединение кубов:
- Кольцевая топология: каждый куб соединен со следующим
- Глобальная адресация: `global_id = cube_id × processors_per_cube + local_id`
- Обеспечивает регулярность и отказоустойчивость

### Поиск пути (BFS):
- Обход графа по уровням
- Гарантирует нахождение кратчайшего пути
- Первый найденный путь = оптимальный
- Сложность: O(2^n × n)

### Преимущества гиперкубической топологии:
- **Малый диаметр:** O(log N) для N процессоров
- **Высокая связность:** много альтернативных путей
- **Масштабируемость:** легко добавлять процессоры
- **Эффективная маршрутизация:** простые алгоритмы поиска пути
